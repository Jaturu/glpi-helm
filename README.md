# glpi-helm

[![CI](https://github.com/Jaturu/glpi-helm/actions/workflows/ci.yaml/badge.svg)](https://github.com/Jaturu/glpi-helm/actions/workflows/ci.yaml) [![Security status](https://img.shields.io/endpoint?url=https://raw.githubusercontent.com/Jaturu/glpi-helm/main/docs/security-status.json)](docs/security-status.md)

A Helm chart and container image for running [GLPI](https://glpi-project.org/)
on Kubernetes: non-root, read-only root filesystems, and compatible with the
`restricted` Pod Security Standard.

| Component | Location | Published as |
|-----------|----------|--------------|
| Helm chart | [`charts/glpi`](charts/glpi) | Helm repository `https://jaturu.github.io/glpi-helm` and `oci://ghcr.io/jaturu/charts/glpi` |
| Container image (php-fpm) | [`image/`](image) | `ghcr.io/jaturu/glpi:<GLPI version>` (amd64 + arm64) |

Each image platform is scanned (Grype + Trivy) before release, signed keyless
with cosign, and published with SBOM, scan reports and provenance. The OCI
chart is signed too. See [Supply chain](docs/supply-chain.md) and the weekly
[security status](docs/security-status.md).

## Quick start

```console
helm repo add glpi https://jaturu.github.io/glpi-helm
helm repo update
helm install desk glpi/glpi \
  --namespace glpi --create-namespace \
  --set glpi.url=https://glpi.example.com
```

The chart installs the GLPI database on first start. Expose the Service with
an HTTPRoute or Ingress (see [Exposure](docs/exposure.md)) and sign in as
`glpi` / `glpi`. GLPI ships four default accounts (`glpi`, `tech`, `normal`,
`post-only`). Change their passwords or disable them immediately.
For a production install, follow [Installing](docs/installing.md).

```
Makefile              Local build, lint and docs targets
```

## Development

The GLPI version is set in one place: `appVersion` in
`charts/glpi/Chart.yaml`.

```console
make version      # GLPI version from Chart.yaml
make test         # lint + template unit tests + schema validation
make test-image   # build the image and run its contract tests
make scan         # the release vulnerability gates, locally
make lint         # helm lint
make docs         # regenerate charts/glpi/README.md (needs helm-docs)
```

CI (`.github/workflows/ci.yaml`) runs the same tests and the vulnerability
gates on every pull request. Merging to `main` runs `release.yaml`, which
publishes the image when `image/` or `appVersion` changed, and the chart when
its `version` was bumped. `rescan.yaml` re-scans the published image weekly.
Dependabot keeps actions, the base image and test tooling current.

`charts/glpi/README.md` is generated. Edit `README.md.gotmpl` or the
`# --` comments in `values.yaml`, then run `make docs`.
